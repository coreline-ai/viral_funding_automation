# 콘텐츠 3종 채널 적합성 검증

검증 일시: `2026-08-16 KST`

검증 대상: `memory_node_graph` 첫 출시팩의 `short-post.md`, `community-post.md`, `long-post.md`

구현 반영 상태: `2026-08-16 최소 수정 완료`

## 구현 후 상태

| 생성물 | 현재 대상 채널 | 구현 결과 |
|---|---|---|
| `short-post.md` | X 단일 게시물 | Markdown 제목 제거, X 가중 문자 계산·280자 초과 복사 차단 적용. `memory_node_graph` 실제 결과는 `110 / 280` |
| `community-post.md` | GeekNews Show | Show 구분, 대표 링크, 기능, 라이선스, 현재 한계, 피드백 질문 구조 적용. 첫 게시에는 검토된 `final/geeknews-show.md` 우선 사용 |
| `long-post.md` | DEV Community | 문제·접근 방식·구현·실행·한계·라이선스·수동 보강 체크 구조 적용. 실제 경험과 예제를 채우기 전에는 게시 불가 상태 표시 |

GUI 탭도 `X`, `GeekNews Show`, `DEV 기술 글`로 변경했으며 Show HN 자동 생성 제외 안내를 추가했다. 아래 내용은 수정 전 초안에 대한 최초 검증 기록이다.

## 결론

검증 당시 콘텐츠 3종은 **사이트별 완성 원고가 아니라 길이와 정보량만 다른 범용 초안**이었다. 따라서 당시 상태로 “각각의 바이럴 사이트에 바로 게시할 수 있다”는 판정은 불가했다.

현실적인 대상 채널을 다음처럼 대응해 검증했다.

| 생성물 | 자연스러운 대상 채널 | 판정 | 핵심 이유 |
|---|---|---|---|
| `short-post.md` | X 단일 게시물 | `수정 필요` | Markdown 제목을 포함하면 일반 게시물 280자 가중 한도를 넘고, 제거해도 여유가 거의 없다. 문장도 프로젝트명이 반복된다. |
| `community-post.md` | GeekNews Show | `초안 부적합` | 형식은 맞지만 생성형 기능 목록에 가까워 제작 동기·구체적 문제·현재 한계가 부족하다. 별도 최종본 `final/geeknews-show.md`는 게시 가능한 수준이다. |
| `long-post.md` | DEV Community 기술 글 | `부적합` | 161단어의 기능·기술 목록으로, 실질적인 기술 본문·설계 과정·실행 예제가 없다. 홍보와 백링크가 주목적으로 보일 위험이 높다. |

Show HN은 위 3종 중 대응되는 완성 원고가 없다. 공개 데모 자체는 직접 체험 조건을 충족하지만, 별도의 영어 제목과 사람이 직접 쓴 설명이 필요하다.

## 1. 짧은 소개 → X

### 공식 기준

- 일반 게시물은 최대 280 가중 문자다.
- 한글을 포함한 CJK 문자는 대부분 2자로 계산된다.
- URL은 실제 길이와 관계없이 23자로 계산된다.

공식 근거:

- https://docs.x.com/fundamentals/counting-characters
- https://help.x.com/en/using-x/how-to-post-a-link

### 실측

| 상태 | 추정 가중 길이 | 판정 |
|---|---:|---|
| 파일 전체를 그대로 복사 | 약 `288` | 한도 초과 |
| `# 짧은 글` 제목 제거 | 약 `277` | 형식상 가능하지만 여유 3자 수준 |

### 콘텐츠 품질 문제

- `AI Systems Atlas`가 한 문장 안에서 반복된다.
- “빛나는 그래프”는 시각적 특징은 전달하지만 해결하는 문제는 설명하지 못한다.
- GitHub Issue 요청까지 한 게시물에 넣어 정보 밀도가 낮다.
- 현재 GUI의 복사 기능은 Markdown 제목까지 포함하므로 X에 바로 붙여 넣는 용도로는 안전하지 않다.

### 판정

`직접 게시 불가`. X 전용 템플릿으로 제목을 제거하고, 한 문장 문제 정의 + 데모 링크 중심으로 240 가중 문자 이하로 다시 써야 한다.

## 2. 커뮤니티 소개 → GeekNews Show

### 공식 기준

- 본인 또는 소속 조직이 만든 서비스·오픈소스는 `뉴스`가 아니라 `Show`로 등록해야 한다.
- 사용자가 직접 체험할 수 있어야 하며, 가능하면 가입이나 이메일 없이 바로 실행되어야 한다.
- 가입 후 일주일이 지나야 링크 등록이 가능하다.
- 반복 등록, 단축 URL, 업보트 요청, 검토 없이 대량 생성된 요약형·SEO형 글은 제한 또는 삭제될 수 있다.
- 본문은 CommonMark를 지원하지만 이미지는 지원하지 않는다.

공식 근거:

- https://news.hada.io/guidelines
- https://news.hada.io/terms

### 생성 초안 검증

통과 요소:

- 실제 공개 데모가 있고 로그인 없이 실행된다.
- GitHub 원본 링크를 사용한다.
- 업보트·Star·후원을 요청하지 않는다.

미달 요소:

- 제작 동기가 `만들었습니다` 한 문장뿐이다.
- 이모지 기능 목록 중심이라 대량 생성된 홍보 요약처럼 보일 수 있다.
- 정적 읽기 전용 데모와 로컬 전체 기능의 차이를 밝히지 않는다.
- 제목에서 프로젝트명이 반복된다.

### 최종본 검증

`final/geeknews-show.md`는 다음을 보완했다.

- Markdown 문서가 쌓이며 관계 파악이 어려웠다는 구체적 제작 동기
- Remark AST, 노드 유형, 근거 경로, Three.js 탐색 방식
- 로그인 없는 공개 데모
- 정적 snapshot과 Node.js 22.13+라는 현재 한계
- 특정 사용 경험을 묻는 구체적인 피드백 질문

### 판정

- 자동 생성된 `community-post.md`: `직접 게시 부적합`
- 검토·수정된 `final/geeknews-show.md`: `콘텐츠 적합`
- 운영 게이트: GeekNews 로그인과 가입 후 1주 경과 확인이 남아 있다.

## 3. 상세 소개 → DEV Community

### 공식 기준

- 게시물은 개발 주제에 맞고 품질이 있어야 한다.
- 홍보 또는 백링크 생성을 주목적으로 해서는 안 된다.
- 외부 링크만 소개하는 수준이 아니라 본문 자체에 실질적인 내용이 있어야 한다.

공식 근거:

- https://dev.to/terms#11-content-policy

### 실측과 문제

- 전체 분량은 약 `161단어`다.
- 기능, 기술 태그, 링크를 나열하는 비중이 대부분이다.
- 기존 방식의 문제, 파서 설계, 데이터 모델, 근거 검증 방식, 실행 예제가 없다.
- 독자가 글 자체에서 배울 수 있는 내용보다 프로젝트 클릭 유도가 중심이다.
- DEV 독자에게 맞는 영어 본문 또는 충분히 맥락화된 한국어 기술 글이 준비되지 않았다.

### 판정

`직접 게시 부적합`. 최소한 다음 구조로 독립적인 기술 글을 새로 작성해야 한다.

1. Markdown 문서 검색만으로 해결되지 않았던 문제
2. Remark AST를 선택한 이유
3. 문서·섹션·개념·Phase·Task 노드 모델
4. 구조 관계와 명시 관계를 구분한 방식
5. 출처 경로를 보존하는 방법
6. 로컬 실행 또는 파싱 예제
7. 현재 한계와 설계상 트레이드오프
8. 데모와 GitHub 링크

## 4. Show HN 추가 검증

### 공식 기준

- 직접 만들었고 다른 사람이 바로 실행하거나 만져볼 수 있는 비사소한 프로젝트여야 한다.
- 가능하면 가입이나 이메일 장벽이 없어야 한다.
- 제목은 `Show HN`으로 시작해야 한다.
- 랜딩 페이지·펀드레이저는 대상이 아니다.
- HN 자체에 생성되거나 AI로 편집된 댓글을 게시하면 안 된다.
- HN을 주로 자기 홍보에 사용하거나 업보트·댓글을 요청하면 안 된다.

공식 근거:

- https://news.ycombinator.com/showhn.html
- https://news.ycombinator.com/newsguidelines.html

### 프로젝트 상태

- 공개 데모와 GitHub 저장소가 있어 제품 조건은 충족 가능하다.
- 현재 3종 원고는 한국어 범용 생성 초안이며 Show HN 제목·첫 댓글용으로 승인할 수 없다.
- Show HN은 3종 중 하나를 재활용하지 말고, 운영자가 직접 영어 제목과 제작 배경을 작성해야 한다.

## 최종 운영 판정

| 채널 | 지금 게시 가능 여부 | 다음 행동 |
|---|---|---|
| GeekNews Show | `조건부 가능` | `final/geeknews-show.md` 사용. 계정 로그인·가입 1주를 확인한 뒤 게시 |
| X | `수정 후 가능` | X 전용 240 가중 문자 이하 원고와 실제 화면 이미지 사용 |
| DEV Community | `불가` | 홍보문이 아닌 독립적인 기술 아티클로 전면 재작성 |
| Show HN | `보류` | 앞선 반응과 제품 준비도를 확인한 뒤 사람이 직접 쓴 영어 원고로 별도 진행 |

## 구현에 반영해야 할 최소 변경

현재 MVP의 단순 범위를 유지하면서도 오해를 막으려면 다음 세 가지만 필요하다.

1. 탭 이름을 범용 길이명이 아니라 `X`, `GeekNews Show`, `DEV 기술 글`로 명확히 표시한다.
2. X에는 가중 문자 수, GeekNews에는 Show·계정 게이트, DEV에는 실질 본문 체크를 적용한다.
3. Show HN은 자동 생성 대상에서 제외하고 별도 보류 상태로 표시한다.
