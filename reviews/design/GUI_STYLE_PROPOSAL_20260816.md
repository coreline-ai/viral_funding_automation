# GUI 스타일·테마 제안

작성일: 2026-08-16

## 제품 전제

- 제품: 공개 GitHub URL 하나를 읽고 게시 가능한 콘텐츠 초안 3종을 만드는 개인용 웹앱
- 핵심 사용자: 자신의 오픈소스 프로젝트를 직접 홍보하려는 개발자
- 화면의 단일 임무: `저장소 입력 → 사실 확인 → 콘텐츠 편집·복사`
- 현재 제외: 자동 게시, 로그인, 데이터베이스, 통계 대시보드, 후원 관리

## 참고한 공개 제품

- Typefully: 편집기를 제품 중심에 두고 초안·미리보기·복사를 가까이 배치하는 방식
  - https://typefully.com/
- Buffer AI Assistant: 하나의 소재를 채널에 맞게 변환하고 결과를 즉시 편집하는 방식
  - https://buffer.com/ai-assistant
- GitHub Spark: 하나의 명확한 입력에서 시작해 결과 미리보기로 곧바로 전환하는 방식
  - https://github.com/features/spark
- Taplio: 빈 편집기를 던지는 대신 생성 과정을 단계적으로 안내하는 방식
  - https://taplio.com/

## 최종 추천: Launch Workbench

### 콘셉트

GitHub의 사실성과 전문 편집기의 집중감을 결합한 밝은 작업대다. 마케팅 랜딩 페이지가 아니라 앱을 열자마자 작업을 시작하는 개인용 도구로 설계한다.

### 화면 구조

```text
┌──────────────────────────────────────────────────────────────────┐
│ Coreline Launch Console                         Local workspace   │
├──────────────────────────────────────────────────────────────────┤
│ GitHub 저장소 URL                                               │
│ [ https://github.com/owner/repository                       ] [생성]│
├──────────────────────┬───────────────────────────────────────────┤
│ 저장소 사실           │ 짧은 소개 | 커뮤니티 소개 | 상세 소개      │
│                      │                                           │
│ 프로젝트명            │ [편집 가능한 생성 콘텐츠]                 │

│ MIT · TypeScript      │                                           │
│ Demo 확인됨           │                                           │

```

### 정보 위계

1. GitHub URL 입력과 `콘텐츠 생성` 버튼
2. 저장소에서 확인한 사실
3. 콘텐츠 3종 편집 탭
4. 복사와 다운로드
5. 오류·누락 정보 안내

- 둥근 모서리: 패널 `12px`, 입력·버튼 `8px`
- 그림자: 큰 카드 전체가 아니라 활성 편집 영역에만 얕게 사용
- 배경 그라디언트와 의미 없는 글로우는 사용하지 않음

### 타이포그래피

- 한국어·본문: `Pretendard Variable`, system sans-serif
- 제품명·큰 제목: `Geist`, `Pretendard Variable`
- URL·라이선스·기술 태그: `IBM Plex Mono`, monospace
- 콘텐츠 편집 본문: `16px / 1.75`
- UI 기본: `14px / 1.5`

### 고유한 시그니처

왼쪽 `저장소 사실` 레일을 제품의 시그니처로 사용한다. README, 라이선스, 데모에서 확인된 사실만 녹색 체크로 표시하고 누락된 항목은 주황색 안내로 표시한다. 생성 글이 GitHub 근거에서 나왔다는 점을 시각적으로 전달한다.

### 핵심 상태

- 초기: 예제 URL과 한 줄 설명만 표시
- 분석 중: `저장소 확인 → README 분석 → 콘텐츠 생성` 실제 단계 표시
- 성공: 저장소 사실과 편집 탭 표시
- 선택 파일 누락: 결과는 생성하되 해당 사실 레일에 경고 표시
- 오류: HTTP 상태와 다시 시도 방법을 입력창 바로 아래 표시
- 복사 완료: 버튼 문구를 1.5초 동안 `복사됨`으로 변경

### 반응형

- 1024px 이상: 좌측 사실 레일 + 우측 편집기 2열
- 768~1023px: 사실 레일을 상단 요약 줄로 축소
- 767px 이하: URL 입력, 사실 요약, 콘텐츠 탭을 단일 열로 배치

## MVP에서 만들지 않을 UI

- 효과를 보여주기 위한 가짜 통계 카드
- 왼쪽 전체 메뉴 사이드바
- 자동 게시·예약 캘린더
- 후원·수익 대시보드
- 여러 저장소 목록
- AI 채팅 패널
- 테마 선택기와 다크 모드

## 구현 우선순위

1. 한 화면 웹앱 셸과 URL 입력
2. 기존 GitHub 분석 모듈을 호출하는 API
3. 저장소 사실 레일
4. 편집 가능한 콘텐츠 3종 탭
5. 복사·개별 다운로드·전체 다운로드
6. 모바일 레이아웃과 오류 상태

## 완료 기준

- 터미널 없이 URL 입력만으로 생성 가능
- 결과가 한 화면에서 읽히고 수정 가능
- 콘텐츠 3종을 각각 복사하거나 다운로드 가능
- 원본 GitHub 저장소에는 쓰지 않음
- 데스크톱과 모바일에서 핵심 흐름 사용 가능
