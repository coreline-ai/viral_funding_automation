# implement_20260816_203309.md

작성 일시: `2026-08-16 20:33:09 KST`

이 문서는 GUI 첫 진입에서 사용자가 바로 한 번의 생성 흐름을 이해하고 실행할 수 있게 하며, 생성 후 새로고침에도 마지막 작업을 잃지 않도록 하는 후속 개발 범위를 고정한다.

## 개발 목적

현재 GUI는 콘텐츠 생성 자체는 정상 동작하지만 첫 화면에는 분석 결과가 없고, 생성 결과도 브라우저 메모리에만 있어 새로고침하면 사라진다. 다음의 최소 사용자 흐름을 보장한다.

```text
처음 방문
→ 내 GitHub URL 입력 또는 실제 예제 1턴 실행
→ 콘텐츠 3종 확인·수정
→ 새로고침
→ 같은 브라우저에서 마지막 작업 복원
```

## 개발 범위

- 첫 화면의 빈 상태 문구와 행동 우선순위 개선
- `coreline-ai/memory_node_graph`를 사용하는 `예제로 1턴 실행` 보조 행동
- 예제 버튼도 기존 실제 `/api/generate`를 호출하며 가짜 결과를 사용하지 않음
- 마지막 성공 결과와 사용자가 수정한 원고를 브라우저 `localStorage`에 저장
- 새로고침 시 마지막 작업을 검증한 후 복원
- 복원 결과임을 알리고 최신 GitHub 상태가 필요하면 다시 생성하도록 안내
- 손상되거나 구버전인 저장 데이터는 무시하고 정상 빈 화면으로 복구
- 데스크톱·모바일에서 동일한 1턴 흐름 제공

## 제외 범위

- 서버 데이터베이스와 사용자 계정
- 여러 저장소 작업 이력과 목록 화면
- 자동으로 예제 API를 호출하는 첫 방문 동작
- Playwright 테스트 결과를 사용자의 실제 브라우저에 강제로 주입
- 비공개 저장소와 GitHub OAuth
- SNS 자동 게시, 예약 게시, 성과 분석
- LLM API, 이미지·영상 생성
- `memory_node_graph`의 이미지·그래프·Three.js 사용
- 서버 API·콘텐츠 생성 규칙의 기능 확장

- 현재 `web/app.js`의 저장소·원고 상태는 JavaScript 실행 메모리에만 존재한다.

## 필수 사용자 시나리오

### S1. 내 저장소로 처음 시작

1. 사용자가 공개 GitHub URL을 입력한다.
2. `콘텐츠 생성`을 누른다.
3. 실제 GitHub 분석 중 상태를 확인한다.
4. 성공하면 사실 근거와 콘텐츠 3종을 확인한다.

성공 기준: 기존 생성 흐름을 유지하며 추가 클릭을 요구하지 않는다.

### S2. URL 없이 예제로 1턴 체험

1. 사용자가 첫 화면의 `memory_node_graph 예제로 1턴 실행`을 누른다.
2. 입력창에 예제 URL이 표시되고 기존 생성 흐름이 즉시 실행된다.
3. 성공 후 사용자는 콘텐츠 3종을 수정·복사·다운로드할 수 있다.

성공 기준: 가짜 데이터 없이 한 번의 사용자 행동으로 실제 결과 화면까지 이동한다.

### S3. 생성 후 새로고침

1. 사용자가 원고를 생성하고 일부를 수정한다.
2. 같은 브라우저에서 새로고침한다.
3. 저장소 정보, 활성 탭, 수정된 콘텐츠 3종을 복원한다.
4. `브라우저에 저장한 이전 작업을 복원했습니다` 안내를 표시한다.

성공 기준: 수정 내용이 유지되고 복원 결과가 최신 재분석 결과로 오해되지 않는다.

### S4. 다른 저장소로 전환

1. 복원되거나 현재 열린 결과가 있는 상태에서 새 URL을 입력한다.
2. 수정 내용이 있으면 기존 확인 대화상자를 유지한다.
3. 새 분석이 성공한 뒤에만 저장된 마지막 작업을 교체한다.

성공 기준: 새 분석 실패로 기존 결과와 수정 내용이 소실되지 않는다.

### S5. 저장 데이터 손상 또는 저장 실패

1. 형식이 잘못되거나 버전이 다른 저장 데이터를 발견한다.
2. 해당 데이터만 삭제하고 빈 화면으로 정상 진입한다.
3. 저장 용량·브라우저 정책으로 저장이 실패해도 현재 생성·편집 기능은 계속 동작한다.

성공 기준: 저장 기능이 기존 핵심 기능을 중단시키지 않는다.
