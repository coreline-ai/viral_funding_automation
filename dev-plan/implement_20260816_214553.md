작성 일시: `2026-08-16 21:45:53 KST`

이 문서는 실제 게시를 수행하지 않고, 기존 GUI에서 GeekNews Show 게시 직전 확인과 기준점 기록을 끝낼 수 있게 하는 최소 개발 범위를 고정한다.

## 개발 목적

- 현재 생성 결과 화면에서 GeekNews Show 공식 규칙과 게시 준비 항목을 확인한다.
- 게시 직전 공개 GitHub 기준점(Star·Fork·Open Issue/PR)을 자동 기록한다.
- 사용자가 최종 원고를 검토하고 수동 Traffic 캡처 여부까지 체크한 뒤 게시 준비 문서를 내려받는다.
- 실제 등록과 계정 인증은 사용자에게 남겨 자동 게시·로그인 범위 확장을 막는다.

## 개발 범위

- GitHub 공개 metadata의 Star·Fork·Open Issue/PR 수집
- `/api/generate` 응답에 생성 시점 기준점 포함
- `/api/baseline`으로 게시 직전 기준점만 다시 수집
- 결과 화면에 GeekNews Show 게시 준비 패널 추가
- 공식 이용법·Show 페이지 링크, 수동 체크리스트, 완료 상태 표시
- 브라우저 저장·복원에 기준점과 체크 상태 포함
- 완료된 게시 준비 문서를 Markdown으로 다운로드

## 제외 범위

- GeekNews 로그인 또는 계정 생성일 자동 조회
- GeekNews 글 자동 등록·폼 자동 입력·업보트
- GitHub Traffic API 자동 조회
- GitHub token을 브라우저에 노출하거나 저장
- 채널 다중화, 캠페인 DB, 성과 대시보드, 후원 기능

## 문서 기반 제약 사항

- GeekNews는 글 등록에 가입 후 일주일 경과를 요구하므로 자동 판정하지 않고 사용자가 체크한다.
- 본인 또는 소속 조직의 프로젝트는 반드시 `Show`로 등록한다.
- Show는 가입·이메일 입력 없이 직접 체험 가능한 작업물을 권장한다.
- 동일 저장소 반복 등록과 검토 없는 대량 생성 문안을 피한다.
- GeekNews 본문은 이미지를 지원하지 않으므로 대표 이미지는 별도 출시팩 자산으로 유지한다.

## 최종 결과 요약

- GitHub repository metadata 한 번으로 공개 기준점을 수집하는 `/api/baseline`을 추가했다.
- 생성 응답과 갱신 응답에 ISO 수집 시각, Star, Fork, Open Issue/PR 수를 포함했다.
- 결과 화면에 GeekNews 공식 링크, 공개 기준점, 수동 체크 5개와 게시 준비 Markdown 다운로드를 추가했다.
- 체크와 기준점은 기존 `v1` workspace에 선택 필드로 저장해 이전 payload도 복원한다.
- 기준점 갱신 시 Traffic 수동 캡처 체크를 초기화하고, 커뮤니티 원고 수정 시 최종 검토 체크를 초기화한다.
- 실제 `memory_node_graph` 검증 값은 Star `1`, Fork `0`, Open Issue/PR `0`이었으며 generation·baseline API가 모두 HTTP 200이었다.
- Playwright에서 체크 5개 완료 → READY → Markdown 다운로드, 새로고침 복원, 원고 수정 후 잠금 복귀를 확인했다.
- 360px에서 `scrollWidth 360 === innerWidth 360`을 확인했다.
- 전체 자동 테스트 `26/26`과 문법·시크릿·whitespace 검사가 통과했다.
- 브라우저 QA의 계정·Traffic 체크는 기능 검증을 위한 테스트 상태이며 실제 사용자의 계정 연령이나 Traffic 캡처 완료를 의미하지 않는다.
- GeekNews 로그인·계정 조회·폼 입력·실제 게시·GitHub Traffic API는 구현하지 않았다.
