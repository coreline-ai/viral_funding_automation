## 개발 목적

저장소 한 개를 실제 출시해 제3자 수요와 반복 작업을 먼저 검증한다. W7 Go/No-Go를 통과한 경우에만 근거 기반 출시 콘텐츠와 `FUNDING.yml` Draft PR을 만드는 파일 기반 TypeScript CLI를 구현한다.

핵심 가설:

1. 프로젝트를 정비하고 적합한 채널에 출시하면 제3자의 방문·사용·피드백이 발생한다.
2. 두 번 이상의 출시 과정에서 같은 준비 작업이 반복되어 자동화할 경제적 가치가 생긴다.

## 문서 기반 제약 사항

1. 공개 저장소도 운영자 승인 전에는 `OPEN_SOURCE`로 확정하지 않는다.
2. `UNKNOWN`, 라이선스 충돌, 승인 만료 상태에서는 캠페인과 후원 PR을 차단한다.
3. 콘텐츠 기능 주장은 승인된 `RepoBrief Lite` claim만 사용한다.
4. claim은 `commitSha`, 파일 해시, 실제 인용문으로 재검증 가능해야 한다.
5. LLM confidence 값은 저장하거나 승인 근거로 사용하지 않는다.
6. `main` 직접 Push를 금지하고 Draft PR만 사용한다.
7. 동일 변경을 두 번 실행해도 열린 PR은 한 개여야 한다.
8. 공개 산출물에 토큰과 비공개 저장소 내용이 포함되면 안 된다.
9. 데모 URL은 운영자가 승인한 allowlist만 사용한다.
10. 플랫폼 정책과 비용은 구현 직전에 공식 문서로 다시 확인한다.

| 채널 유입 | referrer 또는 캠페인 링크에서 1개 이상 |

- [ ] 자동화 후보는 실제로 두 번 이상 발생했다.
