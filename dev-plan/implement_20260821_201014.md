# implement_20260821_201014.md

작성 일시: `2026-08-21 20:10:14 KST`

이 문서는 소셜 플랫폼의 실제 자동 게시 호출을 만들기 **직전**까지 필요한 제품·보안·운영 준비를 고정한다. 이 계획의 종료점은 `최종 승인된 게시 요청을 dry-run으로 검증하고 사람이 수동 게시 또는 다음 자동 게시 개발을 선택할 수 있는 상태`다. 외부 플랫폼에 게시물을 생성하는 API 호출은 이 계획에 포함하지 않는다.

## 개발 목적

1. 현재의 로컬 원고 작업본을 채널별 **승인 가능한 게시 snapshot**으로 발전시킨다.
2. 계정·Developer App·권한·미디어·커뮤니티 규칙 같은 외부 선행조건을 코드 상태와 분리해 명확히 보여준다.
3. 실제 게시 전에도 중복·잘못된 계정·오래된 원고·승인 후 수정·비밀 노출을 차단한다.
4. 첫 자동 게시 후보인 Threads를 기준으로 connector 계약과 dry-run을 완성하되, X·LinkedIn 등은 동일 계약으로 확장 가능하게 준비한다.

## 개발 범위

- `campaign`, `content revision`, `approval snapshot`, `asset`, `account connection`, `publish intent`, `receipt`의 최소 데이터 계약
- 현재 3축 상태에 `connectionStatus`와 `publishIntentStatus`를 더한 자동 게시 전 준비 상태
- 승인 시점의 게시 필드·언어·계정·미디어 hash를 동결하고, 어느 하나라도 바뀌면 승인 무효화
- 플랫폼별 계정/Developer App/권한/검수 상태를 입력·검증하는 GUI와 내보내기 가능한 readiness report
- 자산 파일의 형식·크기·해상도·공개 URL 필요 여부 검증. 업로드·외부 전송은 하지 않음
- connector 공통 인터페이스와 Threads text-post **dry-run adapter**; 요청 body 생성·정책 검증·예상 receipt만 반환
- 중복 방지 키, 명시적 kill switch, 재시도 분류, 감사 로그를 포함한 publish-intent 검증
- X·LinkedIn·Facebook Page·Instagram·YouTube·TikTok·Discord·Bluesky·Mastodon은 공식 API 연결 가능 여부와 구현 순서를 registry로 표시
- Reddit·Show HN·GeekNews·Disquiet·Product Hunt·Peerlist·Indie Hackers·OKKY는 수동 유지, DEV는 비공개 초안까지만이라는 기존 정책 유지

## 제외 범위

- 실제 `POST`/upload/publish/schedule API 호출, 자동 예약, 자동 재시도
- access token·refresh token·client secret을 브라우저, Git, Markdown, localStorage에 저장
- 소셜 계정 비밀번호 로그인, 브라우저 매크로, 비공식 API, 자동 댓글·DM·좋아요·업보트
- 다수 플랫폼 동시 게시, 스레드 중간 실패 자동 복구, 유료 API 요금 자동 결제
- 커뮤니티 수동 채널의 write adapter 구현
- OAuth Proxy(Codex 콘텐츠 생성)와 플랫폼 OAuth(게시 권한)를 혼동하거나 credential을 공유하는 동작
- 외부 기기/LAN 공개. 현재 loopback 경계는 유지

## 문서 기반 제약 사항

- 앱은 현재 공개 GitHub 사실 기반의 수동 게시용 원고를 만들며, 실제 게시 API는 없다.
- `publishReady`는 콘텐츠·운영·사람 승인 3축을 모두 통과한 경우만 true다.
- 플랫폼 token/secret은 현재 앱의 `runtime/` 및 브라우저 저장소에 둘 수 없다. 플랫폼 OAuth 저장 전략은 자동 게시 구현 전에 별도 승인한다.
- Show HN은 작성자가 처음부터 직접 작성해야 하므로 자동화 대상이 아니다. Reddit과 DEV는 현재 `reference_only`다.
- 이번 다국어 지원은 원고 후보 구성 기능이다. 언어별 원어민·커뮤니티 적합성 승인 없이는 게시 intent를 만들 수 없다.

- [x] Phase 2 — `plan-only`: non-secret readiness와 report만 구현. connector, platform OAuth credential, network write는 없음.
- [x] Phase 3 — `new-lesson`: local-only connector, approval/readiness gate, safe receipt만 구현. generic prepublish gate를 typed operation input과 함께 허용해야 snapshot·dry-run 경계가 일치한다.
