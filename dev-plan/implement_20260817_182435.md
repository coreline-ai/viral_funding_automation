작성 일시: `2026-08-17 18:24:35 KST`  
갱신 일시: `2026-08-17 21:40:00 KST`

이 문서는 API Key 방식 대신 **Codex Grok OAuth Proxy 경로**를 이용해 한국어 프로젝트 사실을 서비스별 영문 원고와 영문 요약으로 구성하는 수직 MVP 범위를 고정한다. Grok CLI가 보유한 사용자 OAuth 세션을 재사용하되, 이 앱은 OAuth token을 직접 읽거나 저장하지 않는다.

구현 착수 상태: `IN PROGRESS`. 인증은 `grok login` 세션만 사용한다. `proxy-manager`·sidecar·API Key 경로는 사용하지 않는다.

## 개발 목적

1. 게시용 문구와 내부 체크리스트를 구조적으로 분리해 운영 지시가 번역·복사되는 문제를 제거한다.
2. Grok OAuth Proxy를 통해 단순 직역이 아니라 채널별 형식·톤·필드 제한에 맞는 영어 원고와 영문 프로젝트 요약을 생성한다.
3. 웹 GUI에서 한국어 원문과 영어 번역본을 비교·수정·저장할 수 있게 한다.
4. 번역 후 X·Product Hunt 등 채널별 길이 제한을 다시 검증해 잘못된 원고 복사를 차단한다.

## 기존 `proxy-grok` 재사용 결정

- 확인 기준: 원본 저장소 `main`의 커밋 `d74bd8f`, 원본 작업트리 clean 상태.
- 적용 방식: 원본 패키지와 `proxy-manager`를 통째로 복사하지 않는다. 모듈이 이미 분리되어 있으므로 `text-runner`·`queue`·`config` 안전 실행 패턴만 현재 프로젝트의 Node 22·`.mjs`로 포팅한다.
- 권장 구조:

```text
브라우저
  → 기존 src/server.mjs  POST /api/translate
  → BoundedConversationQueue (concurrency 1)
  → Grok text runner (Fake 또는 CLI)
  → grok --prompt-file --json-schema --single
```

- 별도 HTTP sidecar(`:4358`)와 `proxy-manager` 계층은 만들지 않는다. 기존 로컬 서버에 runner만 연결한다.
- 재사용 대상: 절대 CLI 경로 검증, 정수 환경설정 범위 검사, private workspace, 최소 child environment, 전용 `HOME`, detached process group, timeout·취소 시 `SIGTERM` 후 `SIGKILL`, stdout/stderr 상한, fake runner 주입, bounded queue, 알 수 없는 JSON 필드 거부, request ID 형식 검증.
- 제외 대상: `video.generate`, MP4 artifact 계약, SQLite job store, HTTP Bearer 인증, `proxy-manager`, launchd, Node 24 TypeScript package scaffold.
- 그대로 사용하지 않을 부분: 원본 text readiness는 항상 `ready: true`이고 text runner 전용 테스트가 없으며, 출력도 자유 문자열이다. 이번 프로젝트는 실제 CLI/OAuth preflight, `--json-schema`, 채널별 구조 검증, 도구 호출 차단 테스트를 추가한다.
- 프롬프트가 process 목록에 노출되지 않도록 원본 Grok runner의 `-p <prompt>` 직접 인자 대신 권한 `0600` 임시 prompt file을 사용한다. process group 종료·최소 environment 검증은 원본 Codex runner safety test 패턴을 함께 적용한다.
- 공개 저장소로 옮기기 전에 원본 코드의 소유·재사용 권한을 확인하고, 외부 프로젝트명·서비스 ID·secret 경로가 남지 않게 검사한다.

## 결정 기록

- 원본 Locale은 `ko-KR`, 첫 목표 Locale은 `en-US`로 고정한다.
- Locale 식별자는 BCP 47 형식만 허용한다.
- 첫 MVP는 사용자가 선택한 현재 원고 한 개만 번역한다.
- 채널별 구성 규칙은 `channelProfile`로 분리하고 `locale`, `audience`, `tone`, `publishFields`, `lengthRules`, `ctaPolicy`, `prohibitedPatterns`, `aiPolicy`를 명시한다.
- 인증은 사용자가 사전에 실행한 `grok login`의 OAuth 세션을 Grok CLI가 자체 관리하는 경로만 사용한다.
- 앱은 `grok` headless 명령을 `shell: false`로 실행하고 token 파일이나 bearer 값을 다루지 않는다.
- 자식 프로세스 환경에서 `XAI_API_KEY`를 제거해 API Key 경로로 전환되지 않게 한다.
- Grok에는 현재 채널의 게시 필드, 검증된 프로젝트 사실, 채널 제약만 전달한다. 원본 README 전체와 `internal`은 전달하지 않는다.
- 출력은 JSON Schema로 제한한 영문 요약과 채널별 게시 필드만 허용한다.
- 영문 원고는 한국어 원문을 덮어쓰지 않고 Locale별 별도 상태로 저장한다.
- 한국어 게시 필드나 프로젝트 사실이 바뀌면 기존 영문 요약·원고를 `stale`로 표시하고 복사를 차단한다.
- Show HN은 `translationPolicy: disabled`, DEV는 `draftOnly`, Reddit 등 HOLD 채널은 상태를 그대로 유지한다.
- `/api/generate`는 기존 문자열 `drafts`(18키)를 유지하고, 구조화 초안은 `documents`로 추가한다.
- CLI 24파일은 운영 작업본(게시문 + 체크리스트)을 유지한다. 복사·Grok 입력·`.en-US.md`는 `publishFields`만 사용한다.
- v3 → v4 이관은 구 문자열을 보존한다. 헤더 파싱으로 필드를 복원하지 않는다.
- HOLD 채널은 영문 재구성이 가능해도 기존 복사 제한을 유지한다. 자동 해제 없음.
- Reddit·DEV는 생성 게시문이 아니라 사실·작성 자료다. Show HN은 Grok 실행 전 거부한다.
- 로그인은 `~/.grok/auth.json`을 읽지 않고, `grok` headless 실패의 종료 코드·안내 문구로 `GROK_LOGIN_REQUIRED`를 판정한다.
- prompt는 `grok --prompt-file`과 권한 `0600` 임시 파일을 사용한다.
- 도구는 allowlist를 비운다고 가정하지 않고 `--disallowed-tools`로 shell/file/web/edit를 제거한다. 해당 버전에서 제거를 확인할 수 없으면 실행하지 않는다.
- 서버는 `127.0.0.1`만 유지한다. Grok 세션은 그 머신 사용자의 것이다.
- 실 Grok 1턴은 Phase 2 코드 완료와 별도 게이트다. Fake runner로 로직 테스트를 끝낸 뒤 로그인된 세션 1턴을 확인한다.
