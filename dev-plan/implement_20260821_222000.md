# implement_20260821_222000.md

작성 일시: `2026-08-21 22:20:00 KST`

이 문서는 Threads 원고를 실제 게시 전에 검토하기 위한 **고충실도·읽기 전용 게시물 미리보기** 범위를 고정한다. 구현은 실제 Threads UI의 pixel-perfect 클론이 아니라, 공식 공개 화면에서 확인한 게시물 읽기 구조를 독자 CSS로 시뮬레이션하는 방식만 사용한다.

## 개발 목적

1. 현재 Threads 원고 1~3개의 줄바꿈·URL·연속 게시 순서가 게시물 카드에서 어떻게 읽히는지 확인한다.
2. 현재 선택 언어, approval snapshot, stale 상태가 미리보기와 항상 일치하도록 한다.
3. 모바일과 desktop에서 읽기 폭·줄바꿈 차이를 게시 전에 확인한다.
4. actualPublishCapability, approval, readiness, local dry-run의 기존 안전 경계를 약화시키지 않는다.

## 개발 범위

- Threads 탭에만 `원고 | 미리보기` 하위 보기 추가
- `posts: string[]`의 단일/1~3개 연속 게시 카드 렌더링
- desktop `680px`·mobile `390px` CSS viewport preset
- 현재 원고와 approval snapshot의 일치/미승인/무효(stale) 상태 고지
- readiness에 저장된 공개 `@handle`의 안전한 표시 또는 명시적 placeholder
- 줄바꿈·URL 텍스트·연속 순서를 보존한 `textContent` 기반 renderer
- 비활성 반응 glyph와 비공식 시뮬레이션 고지
- 순수 모델·DOM·브라우저 시각 회귀 테스트

## 제외 범위

- Threads/Meta 로고, 공식 아이콘, 스크린샷, CSS, DOM, iframe의 복제·저장·배포
- 실제 Threads 피드, 탐색, 검색, 로그인, 작성기, DM, 인사이트 전체 복제
- 실제 게시, 업로드, 예약, API/OAuth 요청, token/secret 처리
- 링크 unfurl, 이미지·GIF·투표·텍스트 첨부, 실제 반응 수·검증 배지 표시
- topic tag, 답글/인용 허용 범위, Fediverse 공유 제어의 입력·payload 반영
- X·LinkedIn 미리보기와 공통 UI 프레임워크 추출
- 현재 원고·approval snapshot·readiness schema의 무관한 리팩터링

## 공통 진행 규칙

- 각 Phase는 앞선 Phase의 자체 테스트 완료 후에만 시작한다.
- 원고와 preview model은 현재 선택 locale의 `publishFields.posts`만 사용한다. 번역이 없으면 원문으로 대체하지 않는다.
- 모든 게시 본문은 `textContent`로 넣으며 `innerHTML`, iframe, remote image, external fetch를 사용하지 않는다.
- preview는 approval snapshot·copy·dry-run·connector·publish intent를 생성하거나 변경하지 않는다.
- 외부 Threads API/HTTP write, OAuth token, secret, 비밀번호, 공식 브랜드 자산은 추가하지 않는다.
- 실제 Threads 답글 체인으로 단정하지 않고 `연속 게시 계획`으로만 표시한다.
- 구현 중 발견한 재사용 가능한 문제는 증거와 함께 `plan-only | existing-reference | new-lesson`으로 분류한다.
- 계획에 없는 링크/이미지 preview, 작성기 클론, X·LinkedIn 확장은 별도 계획 전까지 추가하지 않는다.

## 잔여 리스크 / 후속 과제

- Threads UI와 기능은 계정·지역·A/B test·버전에 따라 달라질 수 있다. 배포 전 공식 UI 기준일을 재검토한다.
- 실제 링크 카드·이미지 preview는 Threads crawler 결과와 asset hash 계약이 필요하므로 다음 별도 계획에서만 다룬다.
- topic, reply/quote, Fediverse 표시와 실제 write payload를 연결하려면 공식 API/Developer App 상태를 다시 확인한 별도 계획이 필요하다.
- X·LinkedIn 미리보기는 공통 renderer 추출 대신 각 플랫폼 카드 요구사항을 별도 검토한 후 시작한다.
